# Hub

Coordinate parallel agent sessions for the user. The user drives: they decide what starts,
what merges and what gets removed. The hub keeps the picture current and answers one
question first: **what is waiting on the user, in what order.**

Inline skill: runs in the user's conversation and talks to them.

## Files

The hub is a directory plus a claim on it. The main hub is `.local/ai/hub/` in the current
repository (or the project's local AI storage directory if its instructions name a different
one). A promoted project's hub is `.local/ai/hub/projects/<slug>/`, same layout.
Layout and formats: [reference/files.md](reference/files.md). Templates: `templates/`.

| File | Written by | Purpose |
|------|-----------|---------|
| `stack.md` | the user; the hub only via push/pop/move/claim | active projects, top = focus; hand-owned synopsis lines; claim header; history log |
| `adhoc.md` | the user, or the hub at the user's request | queue items that aren't sessions |
| `sessions/<handle>.md` | the hub at dispatch; the worker after that | one state file per session |
| `hub.md` | generated by refresh only | the view the user reads |

If the hub directory doesn't exist, offer to create it from `templates/` and ask for the
first stack entries.

## Commands

Route the arguments (or the user's plain words) to one of these. No arguments = refresh.

- **refresh** (`/hub`): claim the hub for this session, read every source, regenerate
  `hub.md`, and reply with the "Waiting on you" list and one line per stack project.
  Procedure: [reference/refresh.md](reference/refresh.md).
- **push `<project>` [`--at <n>`]**, **pop `<project>`**, **move `<project>` `<n>`**: edit
  the stack in `stack.md` and append a history line. Push asks for the umbrella ticket or
  link if the user didn't give one. Before pop, list any session whose `serves` is that
  project and ask what they serve now. Then refresh.
- **dispatch `<what>` `--serves <project|adhoc>`**: start a new worker session in its own
  workmux worktree with a handoff that carries the reporting contract, and create its state
  file. Procedure: [reference/dispatch.md](reference/dispatch.md). Without `--serves`, ask,
  offering the stack's projects and "ad hoc".
- **relay `<session>` `<message>`**: deliver a ruling, fix list or instruction to another
  session. Without a session, use the current conversation's subject's session, or ask.
  Procedure: reference/dispatch.md § Relay.
- **clean**: list removable sessions and remove each one the user confirms.
  Procedure: reference/refresh.md § Clean.
- **promote `<project>`**: create `projects/<slug>/` from the templates, point the project's
  stack entry at it, move the state files of sessions serving it there, and tell the user to
  run `/hub --project <slug>` in the session that will be that project's hub. Use only when
  the user asks; the usual reason is a project whose sessions need rulings that bind several
  of them.
- **`--project <slug>`** on any command: act on that project's hub instead of the main one.

## Rules

- **The user drives.** Dispatch, relay and remove only what the user asked for in this
  conversation. Send a batch of relays only after showing the message and getting a yes.
- **Merges and PRs stay on GitHub.** Never run `workmux merge`, `/merge`, `gh pr merge` or a
  local merge into the default branch. When something is ready to merge, it goes in the queue
  as a decision for the user, with the PR link.
- **Idle is not done.** workmux's `done` and ListAgents' `idle` mean the agent stopped, not
  that the work is finished. Session state comes only from its state file. The one use of
  idle: a session that is idle while its file says `queued` or `running` stopped without
  reporting, and goes in the queue as a check (reference/refresh.md).
- **Merged is not done.** A session whose PR merged still owns every step in its
  `after_merge` list. It is removable only when its state is `removable`, or `done` with an
  empty `after_merge`. When in doubt, keep it and ask.
- **Workers own their state.** After dispatch, never change a worker's `state`, `needs` or
  `after_merge`. Report disagreements (a merged PR on a `running` session, a missing worktree)
  in the Drift section and leave the file alone.
- **Synopsis lines in `stack.md` belong to the user or the project's hub.** Refresh derives
  "Now" and "Needs you" and writes them only into `hub.md`.
- **Local paths stay local.** Nothing from the hub directory (paths, handles, handoff files)
  goes into Notion, tickets or PR bodies.
- **Bash missing?** Say in one line which sources couldn't be read (workmux, gh) and continue
  from the files alone.

## Done when

- refresh: `hub.md` regenerated, and the reply starts with the numbered "Waiting on you" list
  (or "Nothing is waiting on you").
- push/pop/move: `stack.md` changed, history line appended, refreshed.
- dispatch: worktree started, handoff ends with the Reporting back block, state file exists
  as `queued`; reply names the branch, handle, and what it serves.
- relay: delivered (or the fallback used) and logged in the session's file; reply says which
  channel was used.
- clean: every confirmed session removed and its state file moved to `sessions/_done/`; every
  other candidate listed with the reason it stays.
